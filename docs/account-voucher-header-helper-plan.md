# Account Voucher Header Helper Plan

## Summary
Add a reusable helper for `accounts.acc_voucher_header` that creates voucher headers with generated numbering fields instead of expecting callers to populate them manually.

## Target Helper
- File: `src/modules/accountsModule/accountVoucherHeader/account-voucher-header.helper.ts`
- Primary API:
  - `createAccountVoucherHeader(client, payload)`
  - `buildAccountVoucherHeaderCreateInput(tx, payload)`

## Numbering Rules
1. `avhVoucherNo`
- Generate from the highest existing `avh_voucher_no` within:
  - `avh_acc_year`
  - `avh_company_id`
  - `avh_branch_id`
- Next value is `max + 1`.

2. `avhVoucherSlno`
- Generate from the highest existing `avh_voucher_slno` within:
  - `avh_acc_year`
  - `avh_company_id`
  - `avh_branch_id`
  - `avh_voucher_type_id`
- Next value is `max + 1`.

3. `avhVoucherRefno`
- Fetch `vchrTypeCode` from `accounts.acc_voucher_types`.
- Build the ref no as:
  - `{vchrTypeCode}-{avhVoucherSlno}`
- Example:
  - `clo-25`

## Payload Contract
Callers send all non-generated header fields in the payload.

Generated by helper:
- `avhVoucherNo`
- `avhVoucherSlno`
- `avhVoucherRefno`

Taken from caller payload:
- `avhAccYear`
- `avhCompanyId`
- `avhBranchId`
- `avhVoucherTypeId`
- all remaining business, audit, and device fields required for insert

## Transaction Contract
- `createAccountVoucherHeader(...)` accepts either:
  - `PrismaService`
  - `Prisma.TransactionClient`
- If a root `PrismaService` is passed, the helper starts its own transaction.
- If a transaction client is passed, the helper stays inside the caller's transaction.
- `buildAccountVoucherHeaderCreateInput(...)` only accepts a transaction client to avoid generating numbers outside the transaction that will insert the row.

## Concurrency Approach
- Use transaction-scoped PostgreSQL advisory locks before reading the current max values.
- Lock scopes:
  - voucher number scope: `accYear + companyId + branchId`
  - voucher serial scope: `accYear + companyId + branchId + voucherTypeId`
- Lock order is fixed so concurrent writers cannot deadlock each other.

## Usage Example
```ts
const header = await this.prisma.$transaction(async (tx) => {
  return createAccountVoucherHeader(tx, {
    avhAccYear: '2025-2026',
    avhCompanyId: companyId,
    avhBranchId: branchId,
    avhVoucherTypeId: voucherTypeId,
    avhVoucherDate: new Date(),
    avhBillRefno: 'BILL-001',
    avhPartyId: partyId,
    avhEmployeeId: [employeeId],
    avhUserId: userId,
    avhDeviceType: DeviceType.WEB,
    avhCounterId: 'COUNTER-1',
  });
});
```

## Validation Rules
- `avhAccYear`, `avhCompanyId`, and `avhBranchId` must be non-empty.
- `avhVoucherTypeId` must be a positive integer.
- The referenced voucher type must exist.
- `vchrTypeCode` must not be blank.

## Testing
Add focused unit coverage for:
- generating the next `avhVoucherNo`
- generating the next `avhVoucherSlno`
- building `avhVoucherRefno`
- rejecting root-client usage for `buildAccountVoucherHeaderCreateInput`
- missing voucher type
- blank `vchrTypeCode`

## Follow-Up
- Current Prisma schema has indexes for voucher number and serial scopes, but not unique constraints for those fields.
- If absolute database-level enforcement is required even for writers that bypass this helper, add:
  - unique constraint on `(avh_company_id, avh_branch_id, avh_acc_year, avh_voucher_no)`
  - unique constraint on `(avh_company_id, avh_branch_id, avh_acc_year, avh_voucher_type_id, avh_voucher_slno)`
